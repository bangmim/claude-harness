# Writing Tistory Blog Posts (mifine.tistory.com)

User's personal Tistory blog has two categories. All posts are saved locally as `.md` under `~/docs/blog/` and manually pasted into Tistory (Open API ended 2024-02, no automated publishing available).

## Core workflow

1. **소재 파악** — User's request + session logs + memory에서 핵심 소재 추출
2. **카테고리 판단** — "카테고리 결정" 섹션 참고
3. **다음 순번 확인** — `ls ~/docs/blog/ | grep -E '^[0-9]+-' | sort -V | tail -1` 로 가장 높은 번호 → +1
4. **마크다운 작성** — "글 템플릿" + "톤 가이드" 반드시 적용
5. **파일 저장** — `~/docs/blog/{순번}-{카테고리}-{제목}.md`
6. **Finder 열기** — `open ~/docs/blog/` 반드시 실행
7. **사용자 안내** — 파일 경로 + 티스토리 복붙 가이드

## 카테고리 결정

**"사이드" (사이드 프로젝트 카테고리) 선택 조건:**
- 특정 프로젝트의 **시간순 진행 로그**
- 아이디어 선정 → 스택 결정 → 구현 → 마일스톤 중 하나
- "번역기+피드 다음 챕터" 등 **시리즈성 축적물**
- 질문: *"이 글이 특정 프로젝트의 이전/이후 글과 연결되는 시리즈인가?"* YES → 사이드

**"오답노트" (개발 오답노트 카테고리) 선택 조건:**
- 특정 삽질·실패·잘못된 가정에서 뽑은 **재사용 가능한 교훈**
- 특정 기술/도구/정책의 함정 (예: Vercel Hobby 상업 불가)
- **1개 토픽, 1편 완결형**, 검색 유입 가능한 보편적 교훈
- 질문: *"이 글이 번역기 외 다른 프로젝트에서도 유용한 교훈인가?"* YES → 오답노트

**둘 다 해당되면:** 양쪽 모두 작성하되 **상호 링크** (`자세한 과정은 [사이드 #N]`, `자세한 교훈은 [오답노트 #N]`). 👉 등의 화살표 이모지는 쓰지 않는다.

## 네이밍 규칙

### 파일명

```
{순번 2자리}-{카테고리 한글}-{제목 한글 kebab}.md
```

- **순번:** 전체 글로벌 발행 순서 (01, 02, ..., 99). 카테고리 섞여도 글로벌 번호.
- **카테고리:** `사이드` 또는 `오답노트` (정확히 이 두 개).
- **제목:** 한글 kebab-case, 특수문자 최소화.

예시:
- `01-사이드-아이디어-7개에서-1개로.md`
- `02-오답노트-무료-호스팅-함정.md`

### 글 안의 제목 (`#` 라인)

사용자 블로그의 실제 제목 포맷을 따른다. **대괄호 prefix 필수**.

**사이드 프로젝트:**
- `# [사이드 프로젝트] {주제}` — 단발성
- `# [사이드 프로젝트] {프로젝트명} -{N}` — 시리즈 (예: `파이썬 주식봇 만들기 -1`)

**개발 오답노트:**
- `# [개발 오답노트] {보편 교훈 한 줄}` — 교훈 중심
- `# [{기술/도구명}] {문제}: {세부}` — 특정 기술 트러블슈팅 (예: `[React Native] datetimepicker iOS 빌드 에러: Incompatible function pointer types`)

**다음 번호 결정 명령:**
```bash
ls ~/docs/blog/ | grep -E '^[0-9]+-' | sort -V | tail -1
```

파일이 하나도 없으면 `01`부터.

## 글 템플릿

```markdown
# [{카테고리/기술명}] {주제}

> {부제 또는 설명 1줄 — 시리즈면 "~시리즈 #N" 또는 "YYYY-MM-DD"}

![{alt text}](https://images.unsplash.com/{photo-id}?w=1200)
*이미지 출처: [Unsplash](https://unsplash.com/photos/{photo-id}) (라이선스 자유 사용)*

## 핵심 요약

- 핵심 결론 3~5개 bullet
- 수치/시점 포함 시 "YYYY-MM 기준" 명시

---

## 왜 이 글을 쓰나

{배경·동기 2~3단락}

---

## 섹션 1~N

{본문. 각 섹션 300~500자. 테이블·코드블록 적극 활용}

---

## 결론 한 줄

> **{단 한 줄 교훈/결론 — bold 처리}**

---

## 다음 포스트 예고 (시리즈면 포함)

- **#NN** {제목} ({카테고리})

---

<small>※ 본 글의 수치·요금·플랫폼 상태는 {YYYY-MM} 기준이며, 각 서비스 정책 변경에 따라 달라질 수 있습니다. 특정 서비스에 대한 평가는 특정 관점의 분석이며, 다른 용도에선 다를 수 있습니다.</small>

<small>※ 이 글의 초안 구조화와 교차 리서치 과정에 AI(Claude)를 보조로 활용했습니다. 사실 확인·판단·최종 서술은 필자 책임입니다.</small>
```

## 톤 가이드 (반드시 적용)

사용자 블로그(https://mifine.tistory.com)의 실제 톤은 **담백한 평어체 개발자 메모**다. 비즈니스 블로그체·자의식 과잉·과장 수식을 피한다.

**어미 — 평어체 통일:**
- 사용: `~다`, `~한다`, `~했다`, `~이다`, `~된다`
- 피함: `~입니다`, `~했습니다` (존댓말), `~라구요`, `~죠?` (구어체)
- 사용자의 실제 문장 예:
  - "인프런 강의를 들으며 정리하는 기록이다."
  - "포트폴리오를 다시 만들어야겠다고 생각했다."
  - "다음 글에서는 실제로 데이터를 불러와서 다뤄볼 예정이다."

**자의식·과장 표현 금지:**

| 피할 표현 | 사용할 표현 |
|---|---|
| ~는 로그다 / ~는 교훈이다 (자의식) | 그냥 본문으로 흘림 |
| ~라는 점이다 (강조 중첩) | ~이다 |
| 압도적 1위 / 유일 생존 후보 | 선점이 명확 / 유일하게 남은 후보 |
| 치명적 약점 / 생사가 갈림 | 큰 약점 / 중요한 분기점 |
| 완패 (영역/상태) | 경쟁 열세 / 선점이 명확한 |
| 폐기 | 제외 / 후보에서 제외 |
| 포화 (반복 시) | 경쟁이 치열한 / 플레이어가 많은 |
| 요금 알림 폭탄 | 예측하기 어려운 과금 |
| 종량제 트라우마 | 종량제에 대한 심리적 부담 |
| 약관 위반 | 약관상 허용되지 않음 |
| 뚫을 각이 없음 | 진입 난이도가 매우 높음 |

**이모지:**
- 본문에 이모지(👉, 💡, ✅, 🚧 등) 사용 금지. 사용자의 실제 블로그는 이모지가 없다.
- 예외: 아이디어 뱅크 내부 파일(발행 안 됨)과 복붙 가이드 문서는 허용.
- 표 안의 `✅/✘` 같은 비교 심볼은 허용 (의미 전달용).

**분량·구조:**
- 한 글 **본문 2000~4000자** (현재 7000~9000자 글은 과함)
- 각 섹션 300~500자, 섹션 수 3~6개가 자연스러움
- 리드 문단은 **1~2줄**, 바로 본문으로 진입

**수치·수상 안전처리 (허위사실 리스크 회피):**
- 공식 재검증 안 된 수치: 삭제 or `"업계 보도 기준"` / `"공개 자료 기준"` 단서
- 요금: `"YYYY-MM 기준"` 명시 (수시 변경)
- 미검증 수상 (Forbes 등 공식 리스트에서 재확인 안 된 것): **삭제가 안전**
- 다운로드 수: `"500만+ (업계 보도 기준)"` 포맷

**AdSense 정책 체크:**
- 경쟁사 "비방" 톤 X → "장단점" / "~한 경우엔 적합하지 않음" 포맷
- 스크린샷 무단 사용 X

## 이미지 선택 (Unsplash 우선)

- Unsplash는 상업 사용 자유, attribution 선택적이지만 매너로 출처 명시
- 발행 전 **반드시 유효성 검증**:

```bash
curl -sI -o /dev/null -w "%{http_code}\n" "https://images.unsplash.com/photo-xxx?w=1200"
```

200 OK만 사용. 404면 다른 ID로 교체.

**검증된 안전 photo ID 재사용 가능:**
- `photo-1557804506-669a67965ba0` (sticky notes brainstorm)
- `photo-1551288049-bebda4e38f71` (laptop analytics)
- `photo-1518770660439-4636190af475` (circuit board)
- `photo-1485827404703-89b55fcc595e` (robot hand)
- `photo-1495001258031-d1b407bc1776` (keyboard)
- `photo-1484480974693-6ca0a78fb36b` (laptop checklist)
- `photo-1507925921958-8a62f3d1a50d` (binoculars)
- `photo-1452626212852-811d58933cae` (runner)
- `photo-1456324504439-367cee3b3c32` (whiteboard planning)

주제별 추천:
- 아이디어/브레인스토밍 → sticky notes, mind map
- 코드/스택 → circuit board, keyboard
- 리서치/분석 → binoculars, laptop
- 플래닝/프로세스 → whiteboard
- 자동화/AI → robot hand

## 작업 완료 후 반드시 실행

```bash
open ~/docs/blog/
```

Finder가 열리면서 저장된 파일 바로 확인 가능.

## 사용자에게 안내할 복붙 가이드

```
파일 경로: ~/docs/blog/{순번}-{카테고리}-{제목}.md

티스토리 복붙 순서:
1. 글쓰기 → 처음부터 "마크다운" 모드 선택 (중간 전환 X — 포맷 깨짐)
2. .md 파일 전체 복사 → 붙여넣기
3. 미리보기로 테이블·코드블록·이미지 확인
4. 카테고리 설정:
   - "사이드-" → "사이드 프로젝트" 카테고리
   - "오답노트-" → "개발 오답노트" 카테고리
5. 상호 링크(예: "👉 [오답노트 #02]")는 발행 후 실제 URL로 교체
```

## 발행 전 체크리스트

- [ ] 제목에 `[사이드 프로젝트] / [개발 오답노트] / [기술명]` prefix 포함
- [ ] 어미 평어체 통일 (`~다 / ~한다 / ~했다`)
- [ ] 자의식·과장 표현 톤 가이드 적용
- [ ] 👉 등 이모지 제거
- [ ] 미검증 수치 안전처리 (단서 추가 or 삭제)
- [ ] 본문 분량 2000~4000자 범위
- [ ] 하단 디스클레이머 2줄 포함
- [ ] Unsplash URL 200 OK 검증
- [ ] 파일명 네이밍 규칙 준수 (`{순번}-{카테고리}-{제목}.md`)
- [ ] 저장 후 `open ~/docs/blog/` 실행
- [ ] 사용자에게 복붙 가이드 안내

## 아이디어 뱅크 운영 (선택)

여러 글을 연재 중이거나 발행 전 소재가 쌓이면 `~/docs/blog/_아이디어-뱅크.md`에 아래 구조로 정리:

```markdown
# 블로그 아이디어 뱅크

## 📝 발행 완료
| # | 카테고리 | 제목 | 발행일 |
|---|---|---|---|

## 🚧 미발행 소재
### #NN — [카테고리] 제목
**각도:** ...
**핵심 포인트:** ...
```

파일명 앞 `_` 는 파일 리스트 상단 고정용.

## Common mistakes

| 실수 | 교정 |
|---|---|
| 제목에 `[카테고리]` prefix 없음 | `# [사이드 프로젝트] 주제` / `# [개발 오답노트] 주제` 포맷 |
| 존댓말 혼용 (`~입니다`) | 평어체 통일 (`~이다 / ~한다`) |
| 자의식 과잉 (`~는 로그다`, `~라는 점이다`) | 그냥 본문으로 흘림 |
| 👉 💡 이모지 사용 | 제거. 상호 링크는 그냥 `자세한 내용은 [오답노트 #N]` |
| 7000자+ 과한 분량 | 2000~4000자, 섹션 3~6개 |
| 순번을 날짜로 매김 (`2026-10-08-...`) | 글로벌 순번 2자리 (`03-...`) |
| 중간에 마크다운 모드 전환 | 처음부터 마크다운 모드 선택 |
| "완패" 등 과격 표현 그대로 | 톤 가이드 매핑 테이블 적용 |
| 미검증 수치/수상 그대로 인용 | "업계 보도 기준" 단서 또는 삭제 |
| 디스클레이머 2줄 누락 | 템플릿 하단 고정 — 삭제 금지 |
| Finder 열기 생략 | `open ~/docs/blog/` 반드시 실행 |
| Unsplash URL 미검증 사용 | `curl -sI`로 200 확인 후 사용 |
