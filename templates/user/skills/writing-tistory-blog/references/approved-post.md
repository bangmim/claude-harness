# 승인된 블로그 스타일 참고

2026-10-14 대화에서 작성하고 사용자가 승인한 EAS Submit 글의 발췌다. 원문 전체 보관본은 아니다. 내용과 수치는 새로운 글의 사실 근거로 사용하지 않는다.

## 제목과 분류

```markdown
# [ReactNative] EAS Submit으로 내부 테스트 제출하기 — 로컬 키 파일 없이 두 앱 연결하기
<!-- 티스토리 카테고리: 개발 오답노트 > ReactNative -->

> production 빌드 다음 단계로, EAS에 저장한 서비스 계정 키를 연결해 제출한 과정
```

## 문장 호흡

새로 가져온 저장소에서 바로 명령을 실행하니 먼저 `expo-router`를 찾지 못하는 오류가 났다. 저장소를 clone한 것과 의존성 설치가 끝난 것은 별개였다. 잠금 파일에 맞춰 설치한 뒤 제출 설정을 확인했다.

처음에는 JSON이 환경변수에 등록되어 있으니 제출에도 쓸 수 있다고 생각했다. 실제로 등록된 이름은 `GOOGLE_SERVICES_JSON`이었다. 알팅의 `app.config.js`는 이 값을 Firebase 연결 파일의 경로로 사용하고 있었다.

여기까지는 Google Play 제출 성공이다. 공개 출시나 심사 통과까지 완료한 것은 아니므로 이후 상태는 Play Console에서 따로 확인해야 한다.

## 재사용할 구성

- 짧은 부제와 핵심 요약으로 시작한다.
- 배경은 이전 글 링크로 연결하고 이미 설명한 내용을 길게 반복하지 않는다.
- 실제로 겪은 증상, 확인한 원인, 선택한 해결책을 연결한다.
- 필요한 명령과 설정 변경 전후를 코드블록으로 보여준다.
- 마지막에는 확인한 결과와 남은 일을 구분한다.
- 불필요한 과장, 억지 후속 예고, 확인하지 않은 완료 주장은 넣지 않는다.
